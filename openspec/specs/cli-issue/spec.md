# CLI Issue Specification

## Purpose

Define `keaveai issue` behavior for submitting content generated by `keaveai init` as a GitLab merge request.

## Requirements

### Requirement: Initialized Content Discovery

The system SHALL discover initialized KeaveAI content from known generated paths before creating an MR.

#### Scenario: Default initialized paths

- **WHEN** user runs `keaveai issue`
- **THEN** the system looks for `keaveai/` and enabled AI tool skill directories such as `.codex/skills/`
- **AND** only existing paths are included in the submission plan
- **AND** the system excludes `keaveai/sdd/` and `keaveai/wiki/`
- **AND** the system maps `.codex/skills/*` files to `global/*` in the target repository

#### Scenario: Custom include paths

- **WHEN** user runs `keaveai issue --include keaveai,.codex/skills`
- **THEN** the system SHALL include only the provided relative paths
- **AND** the system MUST reject absolute paths and paths containing `..`

### Requirement: Target Repository Layout

The system SHALL transform initialized source paths into the target repository layout before staging files.

#### Scenario: Codex skills are submitted under global

- **GIVEN** the source project has `.codex/skills/example/SKILL.md`
- **WHEN** user runs `keaveai issue`
- **THEN** the temporary clone receives the file at `global/example/SKILL.md`
- **AND** `.codex/skills/example/SKILL.md` is not staged in the temporary clone

#### Scenario: Local KeaveAI working directories are excluded

- **GIVEN** the source project has `keaveai/sdd/` and `keaveai/wiki/`
- **WHEN** user runs `keaveai issue`
- **THEN** neither directory is copied into the temporary clone
- **AND** existing `keaveai/sdd/` and `keaveai/wiki/` content in the target repository is not removed by the sync

### Requirement: GitLab Merge Request Push

The system SHALL create a branch from the target repository, commit initialized content as a single extracted-file commit, and push it with GitLab merge request push options.

#### Scenario: Create merge request

- **GIVEN** initialized KeaveAI files have changed in a git working tree
- **WHEN** user runs `keaveai issue --title "Install KeaveAI"`
- **THEN** the system clones the target repository into a temporary directory
- **AND** creates a source branch from the target branch
- **AND** copies initialized content paths into the temporary clone
- **AND** stages copied initialized content paths only
- **AND** commits with the configured commit message
- **AND** pushes to `http://gitlab.metac-inc.com/front/weaveai-database.git` by default
- **AND** targets the `main` branch by default
- **AND** runs `git push` with `merge_request.create`, `merge_request.target`, `merge_request.title`, and `merge_request.description` push options
- **AND** does not prompt for confirmation before creating the commit and pushing the merge request
- **AND** the current project's git history is not pushed

#### Scenario: Default MR title and commit message

- **WHEN** user runs `keaveai issue` without `--title` or `--message`
- **THEN** the merge request title is `sync codex skills and keaveai assets from <project-directory>`
- **AND** the commit message uses the same semantic text

#### Scenario: Dry run

- **WHEN** user runs `keaveai issue --dry-run`
- **THEN** the system SHALL print the branch, target, remote, included paths, target paths, extracted files, and push command
- **AND** the system MUST NOT clone the target repository, create a branch, stage files, commit, or push

### Requirement: Git Safety

The system SHALL avoid mutating the current project's git state when generating an MR.

#### Scenario: Current project history is isolated

- **GIVEN** the current project has many existing commits
- **WHEN** user runs `keaveai issue`
- **THEN** the system MUST NOT push the current project's branch history
- **AND** the generated merge request contains only the single extracted-file commit created in the temporary clone

#### Scenario: No initialized changes

- **GIVEN** all initialized KeaveAI content is already committed
- **WHEN** user runs `keaveai issue`
- **THEN** the system prints that no initialized KeaveAI changes were found
- **AND** exits successfully without creating a branch or pushing

### Requirement: Shell Completions

The system SHALL provide shell completions for the issue command.

#### Scenario: Command completion

- **WHEN** user types `keaveai iss<TAB>`
- **THEN** the shell completes to `keaveai issue`

#### Scenario: Flag completion

- **WHEN** user types `keaveai issue --<TAB>`
- **THEN** the shell suggests supported flags including `--remote`, `--target`, `--branch`, `--title`, `--message`, `--description`, `--include`, and `--dry-run`
